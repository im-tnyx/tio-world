## Architecture design and implementation
- `apps/core/lib/src/ui/components/inputs/tio_input.dart`: `boxedNumber` reuses compact centered numeric font, hint sizing, padding and focus-select-all behavior with standard rounded outlined/focused borders. Core never selects formatter, numeric domain range, kg/lb handling or Save policy.
- `apps/core/lib/src/ui/components/buttons/tio_button.dart`: `supporting` reuses `FilledButton` and `TioButtonTokens` with neutral theme colors and governed pressed/focused/loading/disabled state. Core owns the 46dp minimum target, accessibility and icon-label spacing. It is a semantic supporting action, not a Workout-specific button. Existing primary/secondary/ghost/destructive paths stay intact.
- `apps/features/workout/lib/src/presentation/library/routines/routine_set_input_row.dart`: directly uses `TioInput.boxedNumber` for weight, fixed/Min Reps, Max Reps. Retains `RoutineSetInputLimits`, old controller references/keys, onChanged, and dash range separator.
- Create/Edit Routine pages directly use `TioButton.supporting(label: 'Add Set', leading: Icon(Icons.add), expand: true)`. Edit has only a smaller gap before button, no new layout system. The previously created `routine_add_set_button.dart` wrapper and `_boxedNumberField` helper were **removed** from final branch state.
- `apps/core/lib/src/theme/README.md` documents both new public variant contracts. Existing Core component + Workout widget tests updated for variants and themed geometry.
